# ADR-001: Выбор технического стека и архитектуры мобильного приложения

> **Статус:** Принято (Accepted)  
> **Дата:** 2026-10-26  
> **Авторы:** Fullstack Android Engineer & System Analyst  

---

## 1. Контекст задачи
Нам необходимо разработать Android-приложение для ведения силовых тренировок.  
Ключевые факторы:
1. Залы часто имеют нестабильную связь (подвальные помещения, экранированные конструкции).
2. Пользователь работает с приложением во время физической нагрузки: интерфейс обязан быть отзывчивым, без лагов и задержек сетевых запросов.
3. Требуется высокая надежность сохранения каждого введенного сета (data integrity).
4. Проект должен легко масштабироваться: от автономного локального MVP до облачной синхронизации, трекерных профилей и веба.

---

## 2. Логика рассуждений и рассмотренные альтернативы

### 2.1. Платформа и UI Framework
- **Вариант А: Flutter / React Native (Кроссплатформа)**
  - *Плюсы:* Один код на iOS и Android.
  - *Минусы:* Труднее добиться идеальной работы нативных фоновых сервисов (звуковой/вибро таймер при выключенном экране на разных вендорах Android: Xiaomi, Samsung с агрессивным убийством процессов); оверхед по размеру и производительности.
- **Вариант Б: Native Android (Kotlin + Jetpack Compose)** (ВЫБРАНО)
  - *Плюсы:* 
    - Максимальный контроль над фоновыми процессами (Foreground Service для таймера отдыха, WakeLocks, Haptic Feedback API).
    - Декларативный UI на Jetpack Compose позволяет молниеносно перерисовывать сложные списки подходов и суперсетов с реактивными состояниями (StateFlow).
    - Material 3 Design с Dynamic Color и глубокой оптимизацией под темную тему.
    - Прямая интеграция с Room и Kotlin Coroutines без JNI мостов.

### 2.2. Архитектура приложения
- **Выбор:** Clean Architecture + MVI (Model-View-Intent) / UDF (Unidirectional Data Flow).
- **Слои:**
  1. `domain` — Чистые Kotlin-модели, Use Cases (бизнес-правила: расчет 1RM, валидация сета, таймер, агрегация объема). Не зависит от Android SDK.
  2. `data` — Room Database, DAO, Entity, репозитории, DataStore (настройки единиц измерения кг/фунты), мапперы.
  3. `presentation` — Jetpack Compose экраны, ViewModel, UI State (неизменяемые data class), UI Events (Intent).
- **Обоснование MVI:** 
  Тренировочный процесс имеет четкие дискретные события: `AddSet`, `CompleteSet(id)`, `UpdateWeight(id, val)`, `StartTimer`, `FinishWorkout`. MVI гарантирует отсутствие гонок состояний и детерминированность UI.

### 2.3. Хранение данных (Offline-First Strategy)
- **Технология:** Room (SQLite) + SQLCipher (опционально для шифрования) + DataStore.
- **Обоснование:** 
  Room обеспечивает типобезопасные запросы, поддержку `Flow` для реактивного обновления списков, миграции схемы БД и высокую скорость чтения/записи транзакций. Каждое нажатие чекбокса сета сразу коммитится в SQLite, что исключает потерю данных при разряде батареи или сворачивании ОС.

### 2.4. Фоновые процессы и таймер отдыха
- **Технология:** Android Foreground Service с типом `specialUse` / `mediaPlayback` / `shortService` + уведомление с `NotificationCompat.Builder` (Chronometer / Progress Bar) + SoundPool / VibrationEffect.
- **Обоснование:** Стандартные корутины во ViewModel уничтожаются, если ОС убьет процесс в фоне при выключенном экране. Сервис с постоянным уведомлением гарантирует, что таймер отзвонит вовремя даже на агрессивных прошивках (MIUI / OneUI / ColorOS).

## 3. Итоговое решение
1. **Язык:** Kotlin 2.x
2. **UI:** Jetpack Compose + Compose Navigation + Material 3
3. **Хранилище:** Room Database (Offline-First)
4. **Архитектура:** Multi-module / Clean Architecture (core, feature-workout, feature-exercises, feature-analytics, feature-timer)
5. **Асинхронность:** Coroutines & Flow
6. **Dependency Injection:** Hilt или Koin (Koin для максимальной скорости сборки и отсутствия кодогенерации KAPT/KSP при быстрых итерациях, либо Hilt для стандартного Google стека).

---

## 4. Последствия и риски
- **Плюсы:** Непревзойденная скорость работы, надежность сохранения подходов, мгновенный отклик интерфейса, готовая база для облачной синхронизации.
- **Риски:** Требуется аккуратная настройка энергосбережения для Android 13+ (разрешение `POST_NOTIFICATIONS` и исключение из батарейной оптимизации для таймера).
